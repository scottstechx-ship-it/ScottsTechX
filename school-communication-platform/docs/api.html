School Communication Platform — API Documentation

Base URL: http://localhost:4000/api (configurable with API_BASE_URL in .env). All endpoints except POST /auth/login and GET /health require Authorization: Bearer <JWT>.

Errors are always JSON: { "error": "message" }. Status codes: 200, 201, 400, 401, 403, 404, 409, 413, 429, 500.

Security model: permissions are enforced on the backend for every request. The frontend only hides buttons. A student cannot reach admin endpoints by changing the URL.

Bulk import — /api/imports (admin)

MethodEndpointDescription
POST/imports/uploadCSV/XLSX → headers + sample + importId
POST/imports/validatecolumn mapping → per-row validation & summary
POST/imports/importtransactional import → counts + failures
GET/imports/template.csvstarter template
GET/imports/:id/report.csverror report

Imports are 6-step and review-based: upload → analyze → map columns → validate (duplicates, missing fields, unknown classes, invalid dates/phones/emails) → preview → import. Nothing is written to the database before the admin confirms.

Realtime (Socket.IO)

Connect with auth: { token: JWT }. Rooms: user:<id> (notifications) and conversation:<id> (live messages).

EventDirectionPayload
message:newserver → client{conversationId, message}
message:deletedserver → client{id, conversationId}
notificationserver → client{id, type, title, body, link}
conversation:joinclient → server{conversationId}

The frontend falls back to 15-second REST polling if the socket cannot connect.
